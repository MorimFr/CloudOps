# CIS Identity — delegated permission and capability plan

**Plano somente. Nenhum scope foi concedido, nenhum App Registration alterado e nenhum consentimento solicitado.** Configuração local não comprova grants atuais em qualquer tenant. Identity permanece auth none / permissions [] / enabled=false.

## CURRENT CLOUDOPS PERMISSIONS

- `AuditLog.Read.All`
- `LicenseAssignment.Read.All`
- `User.Read`
- `User.Read.All`

São scopes usados/configurados pelas ferramentas existentes: Graph Connectivity e Inativos. O enum Graph aceito atualmente não contém os novos scopes propostos. Não mudar manifests, combined consent, OBO ou esse enum durante o blueprint. Futuro planejamento por seleção deve incluir apenas o conjunto aprovado da wave, não toda a lista abaixo.

## WAVE 1 ADDITIONS / Wave 1 Minimum Permissions

- `GroupSettings.Read.All`
- `Policy.Read.All`

Esses dois scopes de leitura são adições propostas ao conjunto configurado atual. Admin consent é planejado como obrigatório; o papel de leitura suportado do usuário é requisito independente. Não solicitar Global Administrator por conveniência.

Mínimos atômicos de cada método:

- `GroupSettings.Read.All`
- `Policy.Read.All`
- `Policy.Read.DeviceConfiguration`

A distinção é intencional: deviceRegistrationPolicy admite Policy.Read.DeviceConfiguration como mínimo, mas também Policy.Read.All delegado. Como Policy.Read.All já é necessário para authorizationPolicy/adminConsentRequestPolicy, a união otimizada não pede o scope adicional. [Device registration permissions](https://learn.microsoft.com/en-us/graph/api/deviceregistrationpolicy-get?view=graph-rest-1.0).

GroupSettings.Read.All consta como mínimo na referência atual do método, mas sua presença no catálogo de consentimento deve ser comprovada no lab (Q-GROUP-PERM). Não substituí-lo silenciosamente por Directory.Read.All ou uma permissão de escrita. [Group settings permissions](https://learn.microsoft.com/en-us/graph/api/group-list-settings?view=graph-rest-1.0).

## LATER REQUIRED / Full Identity Automated Permissions

- `AccessReview.Read.All`
- `AuditLog.Read.All`
- `Domain.Read.All`
- `GroupMember.Read.All`
- `GroupSettings.Read.All`
- `LicenseAssignment.Read.All`
- `OnPremDirectorySynchronization.Read.All`
- `Policy.Read.All`
- `RoleManagement.Read.Directory`
- `User.Read.All`

Definição: união otimizada da **coleta técnica estável** dos controles FULL e HYBRID. Isso não promete PASS/FAIL automático para HYBRID e não inclui todos os bloqueios preview. Por seleção, pedir menos: controles não selecionados não justificam scopes adicionais.

Somente os 23 controles FULL planejados, sem coleta auxiliar HYBRID:

- `Domain.Read.All`
- `GroupMember.Read.All`
- `GroupSettings.Read.All`
- `Policy.Read.All`
- `RoleManagement.Read.Directory`
- `User.Read.All`

OnPremDirectorySynchronization.Read.All merece gate especial: a documentação exige Global Administrator delegado, mesmo sendo leitura, e há divergência de forma de URI/resposta. Não é Wave 1 nem requisito genérico para usar CloudOps. [On-premises synchronization](https://learn.microsoft.com/en-us/graph/api/onpremisesdirectorysynchronization-get?view=graph-rest-1.0).

## BETA / PREVIEW OPTIONAL

- `Member.Read.Hidden`
- `Policy.Read.All`
- `Policy.Read.AuthenticationMethod`
- `RoleManagement.Read.Directory`

Policy.Read.All, RoleManagement.Read.Directory e User.Read.All também aparecem em caminhos estáveis: a dependência preview é o endpoint/propriedade, não um scope com nome beta. **Não há justificativa para nova concessão só porque uma chamada usa beta.** Member.Read.Hidden é opcional para grupos ocultos pertinentes, não preview e não solicitado preventivamente. Sem cobertura suficiente, UNKNOWN.

Per-user MFA permanece BLOCKED: beta e N+1 extremo. Authentication-methods preview e isPrivileged beta também ficam fora da execução proposta para Wave 1. [Per-user requirements](https://learn.microsoft.com/en-us/graph/api/authentication-get?view=graph-rest-beta), [hidden membership](https://learn.microsoft.com/en-us/graph/api/group-list-members?view=graph-rest-1.0).

## Regras de minimização

A união segue alternativas explicitamente documentadas, não heurística de que um scope com All cobre qualquer coisa:

| Scope já necessário | Alternativas subsumidas | Motivo |
| --- | --- | --- |
| Policy.Read.All | Policy.Read.AuthenticationMethod, Policy.Read.DeviceConfiguration | Alternativa delegada expressa nos respectivos métodos; Policy.Read.All já é obrigatório nos demais collectors. |
| RoleManagement.Read.Directory | RoleAssignmentSchedule.Read.Directory, RoleEligibilitySchedule.Read.Directory, RoleManagementPolicy.Read.Directory | Alternativa read-only documentada; já necessário para definições/atribuições de função. |

RoleManagement.Read.Directory pode cobrir as leituras de schedules/policies conforme as referências dos métodos. Isso não autoriza usar RoleManagement.ReadWrite.Directory. Para um assessment futuro que selecione apenas aprovação PIM, reavaliar o mínimo específico antes de reutilizar a união do pack inteiro.

Exemplos CIS são metadados da fonte, não plano de concessão. Quando um exemplo omite scopes, isso não significa endpoint sem autenticação; quando inclui escrita, não autoriza escrita no CloudOps. As permissões de MFA registration, por exemplo, são AuditLog.Read.All na API de relatório; não acrescentar UserAuthenticationMethod.Read.All por copiar o script CIS. [User registration details](https://learn.microsoft.com/en-us/graph/api/authenticationmethodsroot-list-userregistrationdetails?view=graph-rest-1.0).

## Licensing / capability context

CIS profile, SKU no tenant, licença atribuída, feature habilitada e acesso da sessão são conceitos distintos. Planejar AVAILABLE / UNAVAILABLE / UNKNOWN com evidência apropriada; indisponível não é FAIL automático. Assinatura de SKU isolada não comprova todos os usuários elegíveis/licenciados ou features operacionais. Não inventar custos financeiros ou remediar licenças.

- **entra-directory:** Configuração de diretório Entra e escopo delegado/papel adequados; não pressupõe SKU específico. Verificar a configuração/autoridade do contexto selecionado.
- **conditional-access-p1:** Conditional Access requer Entra ID P1; perfil M365 E3/E5 não comprova atribuição/estado da licença. [Microsoft](https://learn.microsoft.com/en-us/entra/identity/conditional-access/overview).
- **identity-protection-p2:** Políticas baseadas em risco requerem Entra ID P2, além de CA. [Microsoft](https://learn.microsoft.com/en-us/entra/identity/conditional-access/overview).
- **pim:** PIM: Entra ID P2 ou capacidade Governance aplicável; confirmar usuários e features envolvidos. [Microsoft](https://learn.microsoft.com/en-us/entra/id-governance/licensing-fundamentals).
- **access-reviews:** Distinguir recursos P2 de recursos Governance adicionais; não afirmar que todo Governance está no E5. [Microsoft](https://learn.microsoft.com/en-us/entra/id-governance/licensing-fundamentals).
- **guest-governance-billing:** Governança de convidados requer verificação de condições e billing Azure vinculado, não só SKU interno. [Microsoft](https://learn.microsoft.com/en-us/entra/id-governance/licensing-fundamentals).
- **license-inventory:** Leitura de subscribedSkus e servicePlans auxilia o contexto; não é auditoria completa de licenciamento. [Microsoft](https://learn.microsoft.com/en-us/graph/api/subscribedsku-list?view=graph-rest-1.0).
- **authentication-methods:** Configuração por método e política suportada; entitlement por feature a validar, sem atribuir um SKU universal. [Microsoft](https://learn.microsoft.com/en-us/graph/api/authenticationmethodspolicy-get?view=graph-rest-1.0).
- **authentication-report-p1:** Relatório de métodos requer P1/P2 e papel de leitura; cobertura e frescor separados de licença. [Microsoft](https://learn.microsoft.com/en-us/entra/identity/authentication/howto-authentication-methods-activity).
- **password-protection-p1:** Lista customizada cloud e proteção para usuários sincronizados requerem P1/P2. [Microsoft](https://learn.microsoft.com/en-us/entra/identity/authentication/concept-password-ban-bad).
- **on-premises-password-protection:** Além da licença, exige topologia e agentes on-premises comprovados; configuração cloud isolada não prova implantação. [Microsoft](https://learn.microsoft.com/en-us/entra/identity/authentication/concept-password-ban-bad).
- **smart-lockout-customization-p1:** Smart lockout padrão existe para todos; personalizar requer P1+. Ler configuração não implica exigir personalização. [Microsoft](https://learn.microsoft.com/en-us/entra/identity/authentication/howto-password-smart-lockout).
- **group-creation-policy:** Configuração Group.Unified; divergência documental de licenciamento em Q-GROUP-LICENSE. [Microsoft](https://learn.microsoft.com/en-us/graph/group-directory-settings).
- **entra-laps-tenant-setting:** Habilitação tenant-level de LAPS, disponível no Entra Free+. Cobertura dos dispositivos é outro objeto. [Microsoft](https://learn.microsoft.com/en-us/entra/identity/devices/howto-manage-local-admin-passwords).
- **app-management-policy:** Application management policies constam em Workload ID Free e Premium; não exigir Workload Premium automaticamente. [Microsoft](https://learn.microsoft.com/en-us/entra/workload-id/workload-identities-faqs).
- **entra-connect-password-hash-sync:** Topologia Entra Connect/PHS e acesso à política; cloud-only/federação possuem ressalvas CIS. [Microsoft](https://learn.microsoft.com/en-us/graph/api/onpremisesdirectorysynchronization-get?view=graph-rest-1.0).
- **sspr:** Licenciamento depende de reset cloud versus writeback híbrido; consulta da UI não prova entitlement de todos. [Microsoft](https://learn.microsoft.com/en-us/entra/identity/authentication/concept-sspr-licensing).

M365 E3/E5 e Entra P1/P2 são contexto de perfil/produto; a Microsoft distingue P2 de funcionalidades adicionais do Entra ID Governance e de billing de convidados. O texto genérico do benchmark não deve ser usado como prova comercial de entitlement. [Governance licensing](https://learn.microsoft.com/en-us/entra/id-governance/licensing-fundamentals).

Para Group.Unified há divergência documental real: a referência Graph diz que EnableGroupCreation não exige P1; o guia de restrição de criação descreve P1/P2/EDU para administradores/criadores. Q-GROUP-LICENSE mantém ambas as fontes. Isso não altera o valor false esperado pelo CIS. [Graph settings](https://learn.microsoft.com/en-us/graph/group-directory-settings), [Microsoft 365 group creation](https://learn.microsoft.com/en-us/microsoft-365/solutions/manage-creation-of-groups?view=o365-worldwide).
